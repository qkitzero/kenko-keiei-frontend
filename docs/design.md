# デザインガイド

UI を追加・変更するときはこのガイドに従う。クラス文字列を既存ページから書き写さず、共通コンポーネントとセマンティックトークンを使う。画面が扱う概念と上流サービスの癖は `docs/domain.md` を見る。

**このアプリは事業者が業務で使う管理ツール**。装飾より情報密度と一貫性を優先する。

## カラー

`src/app/globals.css` で3層に分ける。

1. **パレット層**: `--zinc-200` `--blue-700` などの生の色。`globals.css` の外では参照しない
2. **セマンティック層**: `--surface` `--primary` など用途を表す名前
3. **Tailwind テーマ層**: `@theme inline` で `bg-surface` などのユーティリティとして公開

コンポーネントからはセマンティックなユーティリティだけを使う。`bg-zinc-50` のようなパレット直接指定や `bg-[#fafafa]` のような任意値は使わない。

| トークン                          | 用途                                             |
| --------------------------------- | ------------------------------------------------ |
| `background`                      | アプリの地。カードが浮いて見えるよう薄いグレー   |
| `surface`                         | カード・サイドバー・トップバー（白）             |
| `surface-muted`                   | テーブルのヘッダー行など、沈める領域             |
| `border` / `border-strong`        | 罫線 / より強い罫線                              |
| `hover`                           | ホバーの重ね色。半透明なのでどの地の上でも使える |
| `foreground` / `muted` / `subtle` | 本文 / 補助 / さらに弱い                         |
| `primary`                         | 主操作。`danger` の赤と混同しない青にしている    |
| `danger` / `warning` / `success`  | 破壊的操作 / 注意 / 成功                         |
| `placeholder`                     | ローディングスケルトン                           |
| `trend-old` / `trend-new`         | 時点の順序（古い→新しい）。同じ青の濃淡          |

## 寸法

- **コントロールの高さ**: `sm` = 32px / `md` = 36px（既定）/ `lg` = 40px。`src/components/control.ts` に持つ
- **角丸**: コントロールと入力は `rounded-md`、カードとテーブルは `rounded-lg`、バッジは `rounded`。`rounded-full` はアバターだけ
- **影**: ポップオーバーとドロワーだけ。カードは罫線で分ける
- **文字サイズ**: ページ見出し `text-xl` / カード見出し `text-sm font-semibold` / 本文 `text-sm` / 補助 `text-xs`。`text-2xl` 以上は数値の強調にだけ使う
- **余白**: ページ内のブロック間とカード内のセクション間は `gap-6`、フォームの項目間は `gap-4`
- **複数行入力の伸縮**: 縦だけ（`FIELD_SIZE_MULTILINE` の `resize-y`）。ブラウザ既定の `resize: both` は横にも伸ばせるので、隣の列やカードの幅を崩せる。行数は `rows` で決める

## レイアウト

### アプリシェル

**シェルの有無はルートグループで決める**。`src/app/(app)/layout.tsx` が `AppShell` を持ち、シェルが要らない画面（`/register`、`not-found`）はグループの外に置く。`AppShell` 側で `pathname` を見て例外を作らない。**未一致 URL は Next のルーティングでグループの外に落ちる**ので、`AppShell` が 404 をログイン壁に置き換えることがない（root の `not-found.tsx` がルートレイアウトだけを通って描画される）。

- 左の `Sidebar`（幅 224px。`md` 以上で固定表示、未満はドロワー）が**機能への移動**を担う
- 上の `TopBar` が**スコープ**（`TenantSwitcher`）と**アカウント**を担う
- 同じ行き先をサイドバーとトップバーの両方に置かない
- **シェルはサインイン済みか判定中のときだけ出す**。判定中はサイドバーとトップバーを骨組みだけ出し、ナビのリンクは伏せる（押せない導線を出さないため）。未サインインと確定したらシェルごと未サインイン画面に差し替える。トップバーだけ残すと「同じ画面からサイドバーが欠けた」ように見えるうえ、判定中との差分で本文が横にずれる
- **判定中の骨組みは実物と同じ場所を確保する**。ハンバーガーとテナントスイッチャーの枠を空けておかないと、解決した瞬間に見出しが横に押される。スイッチャーの骨組みは**トリガーの上限**と同じ幅にする（実物の幅はテナント名の長さで変わるので、上限より狭いと押される）
- **トップバーのテナント名は文字サイズではなく幅で解く**。型スケール（「寸法」）とコントロール高 `sm` はシェル共通の規則で、長い名前のためにトップバーだけ崩すと隣のアカウントメニューと不揃いになる。トリガーの上限は画面幅に応じて段階的に広げるが、**上限は必ず残す**（無制限だとアカウントメニューを押し出す）。**`sm` 未満では広げない**（狭い画面ではアプリ名に幅が残らない）
- **トップバーの空き幅を数えるときはサイドバーを引く**。`Sidebar` は `fixed` だが `md` 以上では本文の列に `md:pl-56` が掛かるので、**トップバーが使えるのは画面幅 − 224px**。`md`（768px）ではこれで約 484px しか残らず、アカウントメニューは表示名の長さで最大 174px まで伸びる。トリガーを大きく広げられるのは `lg` 以上
- **切り替えメニューの名前は折り返して全文を出す**。選択肢が truncate されると、前方が共通するテナント名を画面上で判別できず、操作対象を取り違える。行数は制限しない（一覧は `max-h-72 overflow-y-auto` の中なので、行が増えてもパネルは伸びない）。パネル自体も広げるが、**`absolute right-0` なので狭い画面では左端からはみ出す**（左方向のはみ出しはスクロールで追えない）。広げるのは `sm` 以上だけにする。`MENU_PANEL` は `AccountMenu` と共用なので、**幅は使う側から渡す**

### ページ

`PageContainer` + `PageHeader` で始める。

```tsx
<PageContainer>
  <PageHeader
    title="顧客"
    description="株式会社テストに登録されている顧客の一覧です。"
    actions={<PrimaryLink href="/customers/register">顧客を登録</PrimaryLink>}
  />
  ...
</PageContainer>
```

- 幅は `PageContainer` が持つ。外枠は常に `max-w-7xl` で、`TopBar` と左端が揃う
- `width="detail"` は入力主体のページ用。外枠は同じまま中身だけ `max-w-4xl` に絞る。**中央寄せにしない**（ページごとに見出しの位置が動く）
- ローディングは `PageSkeleton`。実物と同じ形にする。`shape` で本体の形を選び（`block` = 1ブロック / `list` = ツールバー行 + 表 / `count` = 件数行 + 表 / `section` = セクション見出し + 表 / `home` = 件数タイル + セクション2つ）、要約カードがあるページは `summary`、作成フォームのカードがあるページは `form`、戻るリンクがあるページは `back` を渡す。**ブロックを足したページはスケルトンも足す**（実物より短いスケルトンから切り替わると、解決した瞬間に下のブロックが押し下がる）
- **同じページの中で高さの違うプレースホルダを続けない。** スケルトン → セクション自身のローディング → 実物と2回高さが変わると、下のブロックが2回動く。表の高さは `SKELETON_SECTION_TABLE` のような定数で共有する（`PageSkeleton` と `MeasurementHistory`）
- **全面のメッセージ（`PageMessage`）はページ全体が成立しない場合に限る**（対象が見つからない、セッション切れ、テナント情報の取得失敗など）。未サインインはページ側で分岐しない（`AppShell` が受け持つ）。見出しは成立していて一覧だけ取れなかった場合は、見出しを残したまま一覧の位置に `StateCard` を置く。画面全体を差し替えると、失敗したのが一覧だけなのか画面全体なのかが読み取れない

**詳細ページは「読む」を上、「直す」を下に置く。** 上から**読み取る値（`DetailSummary`）→ その画面の主題（一覧・履歴など）→ 編集フォーム → 識別子 → 破壊的操作**。編集フォームを上に置くと、`fieldset` を積んだぶん（入力1つで60px、`CustomerFields` は16入力で840px）主題が画面外に落ちる。参照実装: `src/app/(app)/customers/[customerId]/page.tsx`、`src/app/(app)/tenants/[tenantId]/page.tsx`（名前の変更とテナントプロフィールを、メンバーと下位テナントの一覧より下に置く）

- **登録フォームを畳んで上に残さない。** 開閉を増やすより順序で表す
- **読み取り表示と編集フォームで同じ項目が重複してよい**。役割が違う（確認 / 変更）
- **操作は行き先で置き場所を決める。** ページ全体から別ページへ移る操作（組織詳細の「測定結果一覧」、測定詳細の「判定結果を見る」）は `PageHeader` の `actions`、セクションの中身に対する操作（測定履歴の「測定を記録」「推移を見る」）はそのセクションの `SectionHeader`。**同じ行き先を両方に置かない**（同じボタンが1画面に2組並ぶ）。主題のセクションを上に出したなら、その操作はセクション側だけで見える位置にある
- ページ内で他の値を待つ表示（最終測定日など）を上に置くときは、**その取得をページ側に持ち上げて子へ渡す**。`src/lib/useResource.ts` はリクエストを共有しないので、同じ URL を2箇所で呼ぶと二重に取る

### ホーム

**ホームはレコードの件数ではなく、未処理の作業を出す。** 顧客数・組織数のようなカウンタは押しても次の行動が決まらない（同じ行き先がサイドバーにある）。主に見るのは測定を記録する現場のスタッフなので、上から**対応が必要（件数タイル）→ 下書きの測定 → 最近の測定**の順に置く。集計の規則は `docs/domain.md` の「ホームの集計」。

- **件数タイルには行き先を付ける。** 「未測定」「注意が必要」はフィルタ付きの顧客一覧（`customerListHref`）へ送る。**ホームで絞り込みを完結させない**（絞り込みは一覧の仕事で、URL に状態が残る）。**例外は、同じページの直下にその実体が並んでいるタイル**（「下書きのまま」）。次に取る行動が同じ画面にあるので、行き先の無い数字にはならない
- **下書きは実体を並べる。** 確定待ちは件数だけでは「どれを開けばいいか」が分からない。行は測定詳細（`/customers/{customerId}/measurements/{measurementId}`）へ送る
- **「下書き」と「最近の測定」を1枚の表に混ぜない。** 前者はやること、後者は記録の確認で、行に対して取る操作が違う
- **上限を伏せない。** 一覧は `SUMMARY_LIST_LIMIT` 件で切るので、超えたら「全25件のうち新しい10件」と全体の件数まで出し、最近の測定には「確定済みの直近10件」と添える
- **集計の前提はタイルの `note` ではなく、タイル群の下に1行で置く。** 対象人数・集計対象外・測定日が未記録の件数は「未測定」「注意が必要」の両方に掛かる条件なので、片方のタイルに書くとそのタイルだけの条件に見える。**タイルの `note` は静的な説明に限る**（データを待つ `note` は、揃うまでそのタイルだけ高さが変わる。スケルトンは `note` の行を確保している）
- **年度に依存する数字はラベルに年度を書く**（`customerStatusLabel` をタイルと一覧の選択肢で共用する）。下書きは年度で絞らないのでラベルにも年度を出さない
- **ページの説明文にページ全体の年度を書かない。** 下書きと最近の測定は年度で絞らないので、見出しに年度を書くと古い日付が誤りのように読める。年度はそれに依存するタイルのラベルにだけ出す
- 主操作は `PageHeader` の「顧客を登録」のまま。**測定の記録は顧客を選んでからしか始まらない**ので、顧客を選ばせない主操作をホームに置かない
- 有効な顧客が居ないテナントでは、0 のタイルと空の表を3つ並べる代わりに `StateCard` 1枚で登録へ送る

### 一覧

一覧は `DataTable` で組む。カラムヘッダー・行リンク・横スクロール・ソートが揃う。件数は `SectionHeader` の `count` か、表の上のツールバー行に出す。

**スクロールはページだけに持たせる。表の中にスクロール領域を作らない。**

- 行全体をリンクにするときは `rowHref` を渡す。先頭セルのリンクが `after:absolute` で行を覆うので、**同じ行に別のボタンを置かない**（覆われて押せなくなる）。行内に操作が要るときは `rowHref` を使わず、先頭セルに `Link` を置く
- 0 件のときは `empty` に `StateCard` を渡す
- **作成フォームを一覧ページに置くか別ページにするかは入力項目の数で決める。** 名前1つなら一覧の上にカードで置く（組織・テナント）、項目が多いなら `PageHeader` の `actions` から登録ページへ送る（顧客は16入力）。**どちらの形でもスケルトンを実物に合わせる**（カードを置くページは `PageSkeleton` に `form` を渡す）
- 幅が足りないときは横スクロールさせる。列を落とさない
- **一覧に UUID の列を作らない。** 業務で読む値ではないのに幅を占める（2〜3列しか無い一覧では列の半分が UUID になる）。識別子は詳細ページの `CopyableId` から取る
- **列は「どの行を開くか」を決められる値にする。** 数だけを出す列（記録された項目数など）は行の中身を表さないので、同じ幅を使うなら結果を表す値（運動器年齢、注意の件数）に替える。行を開かせるためのリンク列（「判定結果」）はこの限りではない
- **列見出しは固定しない。** 横スクロール用のラッパーがあると `overflow-x: auto` が `overflow-y` の計算値も `auto` にするため、`position: sticky` はページではなくラッパーに対して効く。固定するにはラッパー自身に高さを与えて縦もそこでスクロールさせることになり、**ページと表でスクロール領域が2つになる**。入れ子のスクロール領域は焦点が中に無いとキーボードでスクロールできない（`tabindex` が必要になる）ので、一覧が長いというだけの理由で作らない
- **件数が増えてページャや仮想化が要るようになったら、ページ全体を画面の高さに収める形（スクロールは表の領域だけ）へまとめて移す。** そのとき列見出しとツールバーを一緒に固定する。表だけ先に固定して二重スクロールにしない
- ソートは列ヘッダーのボタンで行う。`Column` に `sortKey` を持たせた列だけボタンになり、`sort` / `onSort` で状態を受け渡す。`aria-sort` はコンポーネント側が付ける
- **ヘッダーのボタンはセル全体を覆わせる**（余白を `th` ではなくボタン側に置く）。ラベルだけを包むと当たり判定が文字の高さ（約16px）しか無く、押せそうに見えるセルの余白が反応しない

### 絞り込み

行数が画面に収まらない一覧には、表の上に**ツールバー行**を置く。並びは**左から検索 → フィルタ**、**右端に件数**。

- 状態は**すべて URL のクエリに載せる**（`q` / `organizationId` / `status` / `sort` / `order` / `includeInactive`）。共有・再読込・戻る操作で復元できるようにする
- **書き込みは `router.replace` ではなく `window.history.replaceState`**。App Router と同期しつつナビゲーションも RSC の再取得も起きないので、debounce せず1打鍵ごとに書ける。**遅延させて書くと、直前の操作で書いた値を古いクエリで上書きして取り消してしまう**（`router.replace` はナビゲーションが確定するまで `useSearchParams` が古いままなので、そこから組み直すと同じ事故が起きる）
- **入力欄の `value` を URL の値にしない。** WebKit は `replaceState` を30秒100回で間引くので、URL を唯一の真にすると連続入力で文字が落ちる。入力欄はローカル state を真とし、URL 側の変化は**自分が書いた値と違うときだけ**取り込む（外部からの遷移だけを拾う）
- **テナントを切り替えたら組織のような「そのテナントでしか意味を持たない条件」はクリアする**。検索語と並び順はテナントに依存しないので残す
- 選択肢を上流から取る絞り込みは、**取得に失敗しているとき・選択肢に無い値のときは絞り込み自体を適用しない**。無効化したコントロールが「絞り込み無し」に見えるのに裏で絞り込みが効いていると、解除できない行き止まりになる。同じ理由で、**選択肢が揃わないうちはその列をソート不可にする**（並べ替えたと表示して実際は動かない状態を作らない）
- **絞り込みの条件と表の表示を一致させる。** 「未所属」で絞るなら、表が「—」と描く行は同じ条件で拾えるようにする（解決できない組織 ID を持つ顧客が、そういう顧客を探すためのビューから消える）
- 件数は絞り込み中なら「186件中 12件」、していなければ「186件」にする。どちらの数を見ているのか分かるようにする。入力と同時に変わるので `role="status"` を付ける（変化が読み上げに伝わらない）
- **既定はサーバーの返却順のまま**にし、明示的にソートされるまで並べ替えない
- **日本語の氏名は漢字ではなく読み（カナ）で比較する。** `Intl.Collator("ja")` でも漢字は読み順には並ばないので、氏名列を漢字で比較すると五十音順にならず、カナ列と矛盾した並びになる
- 値が無い行は**並び順の向きに追従させる**（昇順で末尾、降順で先頭）。常に末尾に固定すると「未登録の行を集める」ためのソートができない
- 0 件の空状態は「データが無い」と「条件に一致しない」で**文言を分ける**。後者には条件をクリアする導線を置く
- **一覧の外から取る条件（測定状況など）は、揃うまで表を出さない。** 絞り込む値がまだ無いのに行を描くと、絞り込み前の一覧が一瞬出てから消える。取得に失敗したときは注記を出して条件自体を落とす（「選択肢を上流から取る絞り込み」と同じ扱い）
- **絞り込みの根拠になる値は列に出す。** 「未測定」で絞った一覧に最終測定日が無いと、なぜその行が出たのかを画面で確かめられない。**判定から分からない行は「—」ではなく「不明」にする**（組織未所属の顧客は組織単位の判定に現れないので、測定していないのか分からないのかを取り違えさせない）
- **絞り込みはクライアント側の配列操作で行う**（全件がすでにメモリに載っている）。上流にパラメータが増えたら、UI はそのままでロジックだけ差し替える。参照実装: `src/lib/customerList.ts`

### フォーム

`Card` の中で「`fieldset` + `legend` のセクション + 2カラムグリッド」に分ける。参照実装: `src/components/CustomerFields.tsx`

- 入力は `label` 付きの `TextField` / `Select` / `TextArea` / `Checkbox`。`id` は自動生成され label と関連付く
- **セクションは `h3` ではなく `fieldset` + `legend`**（`FIELD_LEGEND`）。同じラベル（「氏名」「電話番号」など）が別セクションに現れても支援技術で区別できる
- グリッドは `FIELD_GRID`。幅を取る項目だけ `sm:col-span-2` で1行に広げる
- 送信中の無効化は**各入力ではなく `fieldset` の `disabled`** に渡す
- **必須はラベル末尾に ` *`**。任意項目だけのセクションは `legend` に「（任意）」を付ける
- **主操作は `PrimaryButton`**。保存や登録を `SecondaryButton` にしない
- 検証エラーは**送信ボタンの直前**に `text-danger` で1件だけ表示する。カードの外や上部に置くと長いフォームで画面外になり、ボタンが反応していないように見える
- 利用者本人以外の情報を入力するフォーム（顧客など）は、ブラウザが操作者自身の情報を埋めないよう全項目に `autoComplete="off"` を明示する
- 登録画面と編集画面で同じ項目を扱うときは入力群をコンポーネントに切り出す。`values` / `onChange` / `disabled` を受け取り、状態はページ側で持つ

**繰り返す行の中の任意入力は既定で畳む。** 項目ごとに1行を並べるフォーム（測定の記録など）では、行あたりの入力を主となる値だけにする。任意のテキストを値と同じ行に `flex-1` で並べると、空の入力が行のいちばん広い要素になり、値を読み取れなくなる。参照実装: `src/components/MeasurementFields.tsx` のメモ

- **state に持つのは「利用者が明示的に開閉したか」だけにし、既定は値から決める**（`expanded ?? (値がある)`）。マウント時に `useState(値がある)` で固定すると、値が後から入れ替わったときに表示が追従しない
- **入力を空にしただけで欄を閉じない。** 値から導出するだけだと、保存済みの内容を消した瞬間に欄が消えてカーソルが飛ぶ。入力を受け取ったら明示的に開いた扱いにする（`onChange` で `expanded` を立てる）
- **畳んで内容が消える入力を作らない。** 中身があるときは既定で開き、利用者が畳んだときは本文を `text-subtle text-xs` のテキストで見せる。**読み取り画面と同じ見せ方にする**（`src/components/MeasurementValues.tsx` のメモは省略せず全文）
- 開閉ボタンは**押しても何も起きない状態にしない**。「中身があるから畳めない」ではなく、畳んだ先に読める表示を用意する
- 開閉ボタンと開いた入力は**別の名前にする**。同じ `aria-label` を両方に付けると、支援技術ではどちらがボタンか分からない。`aria-expanded` と、開いている間だけ `aria-controls` で入力の `id` を指す（畳んでいるときは指す先が無い）
- 行の中の副次的な操作は `SecondaryButton` の `quiet`。枠と背景のある `default` は入力欄（`FIELD_SIZE` の `h-8` / `h-9` に `border` `rounded-md`）と見分けが付かず、行に入力が増えたように見える
- **`quiet` は枠が無いぶんボタンだと気付きにくいので、開閉には字形を添える**。字形は `TenantSwitcher` の `▾` に合わせ、**行の中で開くものは開いている間 `▴` に入れ替える**（`text-subtle text-xs` の `aria-hidden` な `span`）。どこに開くのかと、もう一度押せば畳めることが見た目で分かる。重ねて出るポップオーバーのトリガー（`TenantSwitcher` / `AccountMenu`）は、パネル自体が見えているので入れ替えない

### 評価の表示

ランクやスコアのような「良し悪しのある値」は、色で意味を伝える前に**文字で意味を書く**。色だけに頼ると、色覚特性や印刷で情報が落ちる。

- **ランクの色は5段階を3色に畳む**。A・B は `success`、C は `muted`、D は `warning`、E は `danger`。C（年代相応）は基準どおりという意味なので、良くも悪くもない `muted` にする。5段階に5色を割り当てると、隣の段階との差が色で読めなくなる
- **バッジには記号だけを入れ、意味は隣の列にテキストで出す**（`[B]` `良い`）。意味をバッジの中に入れると「良い」と「やや注意」で幅が変わり、右側に並ぶ列がガタつく。バッジは中身を包む形のままにしておく
- **3群に畳んだ件数は `RankCounts` を通す**。並びは `RANK_GROUPS` の順（注意 → 年代相応 → 良い）に固定し、画面が変わっても数字の並びが入れ替わらないようにする。区切りの `/` は `aria-hidden` で、読み上げには群の名前と単位を入れる（数字が3つ並ぶだけでは、どれがどの群か音では分からない）
- **意味と数値は幅を固定した列にする**。行ごとに `flex` で組むと列は行の中でしか揃わないので、z スコアと意味は固定幅（右寄せ／左寄せ）にして行をまたいで揃える。値が無い行も同じ枠を残し、「未測定」を意味の列に置く。参照実装: `src/components/ElementEvaluations.tsx`
- 幅が足りない一覧（項目別評価の表）では**意味そのものを省き**、**凡例を表の直後に置く**（`RANK_LEGEND`）
- ランクと色の対応は `src/lib/judgment.ts` の `rankTone` に集約する。表示側で条件分岐を書き写さない
- **上流の列挙値をそのまま画面に出さない。** 知らない値が来たときのフォールバックは `RANK_` のような接頭辞を落として短く保つ。生の列挙名を返すと、固定幅の枠に収めた表示が壊れる

**チャートは値が欠けている前提で設計する。** 測定は部分的に行われるので、軸がすべて埋まることのほうが少ない。

- **欠損を 0 として描かない**。中心に落とすと「非常に悪い」と読めてしまう。点を打たず、軸のラベルを `subtle` にして未測定であることを示す
- 欠損軸をまたぐ辺は結ばない。閉じた図形にするために存在しない値を補間しない
- **面にならない数（3未満）ではチャートを出さない**。一覧だけを見せる（`MIN_RADAR_ELEMENTS`）
- チャートは一覧と**同じ情報の別表現**にとどめ、チャートにしか無い情報を持たせない。SVG は `aria-hidden` にして、隣の一覧を支援技術の読み取り経路にする
- 描画は依存を足さずインライン SVG で行う。色はセマンティックトークンのユーティリティ（`fill-primary` / `stroke-border`）を使う。参照実装: `src/components/ElementRadar.tsx`
- **クラス名を組み立てない**（``className={`stroke-${tone}`}``）。Tailwind が検出できず色が落ちる。色は `stroke-trend-new` のような完成したクラス名で受け渡す

**系列を色で塗り分けない。** このアプリは系列の識別用の配色を持たず、あるのは `primary` とグレー、そしてランクの意味を表す `success` / `warning` / `danger` だけ。意味色を「6要素のうちの3本目」に流用すると、同じ赤が画面のどこかでは「要注意」を、どこかでは「柔軟性」を指すことになる。意味色を避けて6色を組んでも、残る色相が青〜紫に偏り、P型・D型色覚では区別できない（検証で全ペア ΔE 0.4）。**色ではなく形で分ける** — 1枚のグラフに乗せるのは「主役1本＋文脈1本」までにし、それ以上は表に置く。

**色分けしてよいのは順序と状態だけ。**

- **時点の順序**（古い→新しい）は `trend-old` → `trend-new` の濃淡で表す。薄いほど古い。レーダーに重ねるのは2時点まで（3本以上は輪郭が混み合って読めない）。**どの時点を重ねたかはラベルに日付を出す**。「初回」「最新」と書けるのは、それが実際に一覧の端にあたるときだけで、評価が出た測定だけを拾うと端がずれる
- **ランクの色**は `rankTone` の割り当てに従う。分布のような帯にするときは5段階のままにできない（`warning` と `danger` が隣接すると通常の色覚でも ΔE 14.4 で見分けが付かない）ので、A・B / C / D・E の3つに畳む

**推移の縦軸を自動で伸縮させない。** 身長のように 0.1cm しか動かない項目を値の幅に合わせて描くと、測定のばらつきが大きな変動として紙に刷られる。項目ごとに最小の表示幅を持たせ、それ未満の変化は平坦に描く。z スコアのように尺度が決まっている値は固定の幅を渡す。実装は `src/lib/chart.ts` の `chartRange`

**同じ問いに答える表は同じ列構成にする。** 「項目ごとにどう推移したか」に答える表（要素別・運動機能・体組成）は、ランクが付くかどうかに関わらず `項目 → 各測定日 → 推移 → 変化` で揃える。ランクの有無はバッジ列の有無で表し、レイアウトを変える理由にしない。参照実装: `src/components/TrendTable.tsx`

### 印刷

紙に出す画面は**専用ページを作らず、同じ画面に印刷用スタイルを重ねる**。レイアウトを二重に持つと、項目が増えたときに画面だけ直して紙が古いままになる。参照実装: 判定結果画面（`PrintButton` / `PrintFrame`）。

**ボタンは「印刷」と書く。** 押すとブラウザの印刷ダイアログが開き、紙にするか PDF にするかを選ぶのは利用者なので、こちらで PDF と言い切らない。ラベルの意味を補う説明文が要るなら、それはラベルが合っていない。

- **用紙は `globals.css` の `@page` で A4 縦に固定する**。余白もここに持ち、ページごとに変えない
- **配色は画面と同じにする**。`@media print` で上書きするのは `background`（地をアプリのグレーから白へ）と `hover` だけ。ランクの色分けなど、画面で意味を持つ色は紙でも同じ意味を持つ
- **背景色を印刷するには `print-color-adjust: exact` が要る**。既定では背景が落ち、表のヘッダー行やバッジの地色が消える。`:root` に指定して全体へ継承させる
- **操作するものは紙に出さない**。シェル（`Sidebar` / `TopBar`）、戻るリンク、`PageHeader` の `actions`、`StateCard` の `action`、`DangerZone` は各コンポーネントが `print:hidden` を持つ。**呼び出し側ではなく、操作を入れる器の側に付ける**。器ごとに付け忘れると、印刷ボタンが無効な画面から Ctrl+P で刷ったときに「再試行」が紙に出る
- **紙に出す値は、印刷するデータそのものから取る**。他所のコンテキストに ID を引き当てて解決すると、そちらの取得が失敗したときに黙って空欄になる。解決できないなら印刷させない（`PrintButton` を無効にする）
- **入力欄は本文テキストに差し替える**。フォームを `print:hidden` にし、隣に `hidden print:block` の段落を置く。出すのは**保存済みの値**で、編集中の値を紙に出さない（紙と DB が食い違い、同じ紙を後から再現できなくなる）。未保存の変更があるときはその旨を画面に出す
- **横スクロールは印刷で解除する**（`print:overflow-visible` / `print:min-w-0`）。`overflow-x-auto` のままだと紙の幅で切れる
- **列が多い表では、折り返してほしくないセルに `whitespace-nowrap` を付ける。** `print:min-w-0` で `min-w-max` が外れると表の幅は自動レイアウトが決めるが、**日本語はどこでも改行できるので列の最小幅が1文字ぶんまで潰れる**。氏名が「長谷／川 里／奈」のように割れ、見出しも「棒反／応」になる。`whitespace-nowrap` を付けた列は最小幅が文字列全体になり、自動レイアウトがその幅を確保する（バッジしか入らない列がそのぶん詰まる）。それでも入らないときは、詰めるのは**余白**（`print:px-1`）で、文字を折り返させない

**紙にしか出さない補足は `PrintFrame` の `appendix` に渡す。** 本文の後ろに `print:break-before-page` で改ページして置かれ、ヘッダーは本文と同じものが付く。画面には出さない（操作するスタッフには不要で、情報密度を下げるだけ）。参照実装: `MeasurementItemGuide`。

**補足は紙に載っているものだけを説明する。** 項目の一覧を静的に持たず、**その測定が実際に記録した項目**（`measurementDisplayEntries`）を並べ、`code` をキーに文面（`src/lib/measurementGuide.ts`）を引く。文面が無い項目は落とす。マスタ全件から組むと、血圧しか測っていない顧客に握力や 5m 歩行の説明が付いてきて、「この用紙に出ている項目の説明です」という自分の書き出しと矛盾する。算出値の解説も、算出できたときだけ出す。

**上流にしか無いデータを紙のためだけに写経しない。** 運動機能の項目を要素（筋力・バランスなど）で束ねると読みやすいが、`MeasurementItem` は項目と要素の対応を返さないので、いまはカテゴリ単位で並べている。同じ理由で年代別の基準値一覧も載せない（判定に使う値は上流のシードにあり、フロントに複製すると食い違う）。項目ごとの「同年代の平均」は判定 API から来るので、そちらは項目別評価に出る。

**PDF として保存したときのファイル名は `document.title` で決まる。** アプリ名のままだと、どの紙を刷っても同じ名前で保存され、複数の顧客ぶんを保存した時点で区別できなくなる。`PrintFrame` に `fileName` を渡すと `beforeprint` で `document.title` を差し替え、`afterprint` で元に戻す（タブの見出しは変えない）。名前は `printFileName`（`src/lib/print.ts`）で組み立て、**人が読める要素だけ**を並べる（例: `判定結果_山田太郎_2026-08-08`）。書類の種別・対象・日付の順にすると、フォルダに貯めたとき対象ごとに並ぶ。ファイル名に使えない文字はここで落とす。

**一意にするために ID を混ぜない。** 同じ名前で保存しようとするとブラウザと OS が `(1)` を付けるか上書きを確認するので、黙って消えることはない。稀な衝突のために、全ファイル名を機械的な文字列にする価値はない。

**長さの制限は連結後の文字列ではなく、長い要素を削って掛ける。** 連結してから末尾を切ると、氏名が長い顧客だけ日付が落ちて、同じ人の別の測定が全部同じ名前になる。氏名は 255 文字まで登録できるので、これは実際に起こる。

**ページ分割は流し込みにする。** セクションごとに強制改ページすると、誰が出力しても同じページに同じものが載る代わりに、**ページの下半分が空く紙が何枚も出る**。一度そう組んで戻した。紙は上から詰め、割れてはいけない塊だけを指定する。

**割れてはいけない塊と、割れてよい塊を区別する。** `Card` は既定でページをまたがない。ただし**中身が1ページを超えうるカードには `splittable` を渡す**（`MeasurementValues` / `AdviceForm`）。長いカードを塊のまま送ると、直前のページが半分空いたまま次のページへ飛ぶ。代わりに**1行を割れない単位にする**（`DataTable` の `tr`、値の1行、要素別評価の `li`）。見出しがページ末尾に取り残されないよう、`Card` の見出し行と `h3` と `SectionHeader` は `print:break-after-avoid` を持つ。**凡例のように表とセットで意味を成すものは、表と同じ入れ物に入れて `print:break-before-avoid` を付ける**（記号だけのバッジが刷られたページから読み方が消えないようにする）。

**余白は印刷側だけで詰める。** 画面の行間を紙の都合で狭めない。値の行は `print:py-1` で詰めており、測定項目マスタ18項目に備考が付いても測定結果は1ページに収まる。

**ページ番号は出せない。** CSS でページ番号を出す仕組み（`@page` のマージンボックス内の `counter(page)`）を Chrome が実装していない。代わりに**各ページに繰り返すヘッダー**で「誰の・いつの紙か」を示す（`PrintFrame`）。

繰り返しには `position: fixed` を使わない。**Chrome は fixed 要素をページの本文領域に対して配置し、はみ出した分を隣のページへ回すため、`@page` の余白には描けず本文と重なる**。`thead`（`table-header-group`）なら全ページで繰り返され、本文側の領域も確保される。`PrintFrame` はこのためにレイアウト用の `table` を持ち、画面では各要素を `display: block` に戻して素の div と同じに見せる（`.print-document`）。1ページ目にもヘッダーが出るので、画面の見出しと内容が重複することは許容する。フッターが要るようになったら `tfoot`（`table-footer-group`）を同じ形で足す。

**紙に出力日時を刷らない。** Chrome は印刷設定の「ヘッダーとフッター」が ON だと紙の隅に日時・URL・ページ番号を刷る。ページ側からは制御できないので、自前でも日時を出すと同じ情報が二重に載る。

### 破壊的操作

削除など取り消せない操作は `DangerZone` に隔離し、`window.confirm` で確認する。通常のカードと同じ視覚的重みで並べない。

### ナビゲーション文脈の外

サインイン前とプロフィール作成前の画面だけ、シェル無しの中央寄せにする。アプリ内の CRUD 画面にこの形を使わない。

- `/register`（プロフィール作成）: `Card` 1枚
- `/` の未サインイン: アプリ名・説明・`LoginButton`・機能カード。**何ができるアプリかをここで伝える**（サインアップは招待制ではないので、初見の訪問者が来る）。機能カードは `FEATURE_NAV_ITEMS` の `label` と `description` から組み、サイドバーと文言をずらさない（`NAV_ITEMS` には未サインインでは意味を持たない「ホーム」が入る）
- それ以外の未サインイン: 「ログインが必要です」+ 何を見ようとしたか + `LoginButton`。**アプリの説明はここに置かない**（その利用者はもう知っている）
- 行き先の名前は**一覧ページに完全一致したときだけ**使う。`activePrefix` で前方一致させると `/customers/register` が「顧客を表示する」になり、実際の行き先と食い違う

枠組みは `PageContainer centered` / `PageMessage` を使い、中央寄せのクラス文字列を書き写さない。参照実装: `src/components/SignedOut.tsx`

### 認証の状態

`UserContext` は真偽値ではなく `status` を持つ（`loading` / `ready` / `signedOut` / `noProfile` / `error`）。**「ユーザーが取れなかった」を未サインインに潰さない**。401 は未サインイン、404 はプロフィール未作成、それ以外は取得失敗で、出すべき画面が違う（取得失敗はログイン壁ではなく `再試行`）。

ルートレイアウトは認証クッキーの有無を見て `initialStatus` を渡し、初回描画から紹介画面を出す（初見の訪問者とクローラーに骨組みを見せない）。ただし**これは初期表示のヒントに過ぎず、クライアントの確認を省略しない**。`refresh_token` は `SameSite=Strict` なので外部リンクからの遷移では SSR に届かず、「クッキーが無い」は未サインインの証明にならない。ヒントで往復を打ち切ると、ログイン済みの利用者がログイン壁に落ちる。

### ログインの導線

ログインが要る操作は、先に壁を置かず**操作した時点で促す**。ただし**意図を保つこと**が条件になる。

- 戻り先の検証は `src/lib/returnTo.ts` の `sanitizeReturnTo` に集約する。相対パスのみ許可し、先頭セグメントで `api` と `register` を弾く（`/api/` の前方一致だけでは `/api?x=1` が通る）
- 戻り先は**タブ単位の `sessionStorage` を主**、httpOnly クッキーを従にする。クッキーだけだとブラウザ全体で1つしか持てず、2つのタブで同時にログインすると互いの行き先に着地する。サーバーのリダイレクトはクッキーで決め、ズレていればクライアントが `sessionStorage` の値へ寄せ直す
- `/api/auth/login` はクッキーを書く副作用があるので**同一オリジンからの呼び出しに限る**（`sec-fetch-site`）。第三者のページから戻り先を仕込ませない
- 戻り先を捨てて `/` に着地させない。促しが門前払いになる
- プロフィール未作成の利用者は先に `/register` へ送り、**作成後に戻り先へ送る**（`/` で止めない）

## 共通コンポーネント

`src/components/` から選ぶ。props はコードの型定義を見る（ここには書かない）。

| 用途                     | コンポーネント                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------ |
| 外枠                     | `AppShell` / `Sidebar` / `TopBar`                                                    |
| ページの骨格・全面の状態 | `PageContainer` / `PageHeader` / `PageSkeleton` / `PageMessage`                      |
| ブロック                 | `Card` / `SectionHeader` / `DangerZone` / `StateCard` / `StatTile` / `DetailSummary` |
| 一覧                     | `DataTable`                                                                          |
| 入力                     | `TextField` / `Select` / `TextArea` / `Checkbox`（土台は `Field`）                   |
| 操作・状態               | `PrimaryButton` / `PrimaryLink` / `SecondaryButton` / `Badge`                        |
| 識別子の受け渡し         | `CopyButton` / `CopyableId`                                                          |

- **ボタンとリンクを1つのコンポーネントに兼用させない**。`href` と `disabled` / `onClick` が同時に受け取れると、渡しても効かない props が型を通ってしまう
- `className` は基底クラスと**競合しない**追加クラス（`flex-1`, `w-full` など）に使う。余白やサイズのバリエーションは `padding` / `size` の props で表す。足りないバリエーションはクラスをコピーせずコンポーネント側に追加する
- 新しい入力部品は `Field.tsx` の `FIELD_BASE` / `FIELD_SIZE`、新しいボタンは `control.ts` の `CONTROL_*` を使う
- **利用者が書き写す識別子には `CopyButton` を添える**（UUID は目で写すと間違える）。結果はアイコンの差し替え（成功 `success` / 失敗 `danger`）と `role="status"` で伝え、**押しても何も起きない状態を作らない**。クリップボードは非対応・拒否がありうるので、失敗を無視しない
- **詳細ページの識別子は `CopyableId` で最下部**（破壊的操作の直前）に置く。上部に置くと、その画面で読みたい値より先に UUID が来る。素の `font-mono` テキストで出さない（コピーできない識別子を並べても書き写す手間は変わらない）。**例外は、名前を解決できないときに対象を特定するために添える識別子**（`TenantName` の非メンバー・取得失敗）。この場合も `CopyButton` を添え、狭い枠でも読めるよう `truncate` ではなく `break-all` にする
- **読み取る値の並びは `DetailSummary`。** ラベルと値の `dl` で、値が無い項目も `Missing` を残して**項目自体を落とさない**（列がずれて行をまたいで読めなくなる）。まだ取れていない項目は `loading` でスケルトンにする

## 検証とフォーマット

画面をまたいで判定がずれないよう、`src/lib/` の1箇所に置く。

- 文字数上限と制御文字: `text.ts`（`TEXT_MAX_LENGTH` / `isTooLong` / `hasControlChar`）。上限をエンティティごとに再定義すると、数え方（コードポイントか UTF-16 か）がずれてサーバーの判定と食い違う
- 日付の妥当性・未来判定・`yyyy-mm-dd` と `google.type.Date` の変換: `date.ts`
- UUID の形式判定: `uuid.ts`
- 検索語の正規化: `search.ts`（`NFKC` で半角カナ・全角英数を畳み、ひらがな→カタカナ、小文字化）。**`text.ts` に混ぜない**。あちらはサーバーと判定を揃えるためのバリデーション専用で、曖昧一致のための正規化とは目的が違う
- ペイロード組み立て: エンティティごとの `lib/*.ts`（例: `buildCustomerPayload`）
